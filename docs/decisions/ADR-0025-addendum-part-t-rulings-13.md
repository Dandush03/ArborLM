## Ruling 45

**Gate G9 cites seed registry revision 7 in place of revision 6.**

- **Why.** After main (with P10-I-S1 and P10-I-S6) was merged into the P10-I-S2 branch, revision 6's checker printed `RESULT: FAIL`, `problems: 66`. G9 would then fail in the gates stage of every rehearsal and at the freeze (it is not called by calibration), and the frozen Part Q test `tests/test_p10is2_partq_freeze.py::test_seed_gate_passes_on_this_tree_and_detects_a_value_outside_the_rows` failed with it. Same cause and same shape as ruling 42: revision 6 does not list P10-I-S1 and P10-I-S6 as owners of their own files.
- **The 66, all traced.** The checker prints at most 60 failure lines and then "... 6 more", so 60 were printed against 66 counted. Revision 6 run with `--own` for P10-I-S1 and P10-I-S6 gives `RESULT: PASS`, `problems: 0`, with 24 own-files hits for P10-I-S1 (against `configs/p10is1_capacity.toml`) and 42 for P10-I-S6 (against `configs/p10i_s6_flat_lead_persistence.toml`); 24 + 42 = 66. The six not printed are P10-I-S6's own allocation in its own config. None is a collision between studies; the ownership was therefore not widened beyond the two studies.
- **What changed (new files only).** `docs/reviews/p10-i-direction-2026-11-17/seed_registry_check_r7.py` (SHA-256 `1f3b2de22ef3ff9bd01d81d67d7fcccac27710ed3394b62bec9c0688bc8b8f8f`) and `SEED_REGISTRY_R7.md` (SHA-256 `528aa3066e4dfafb09a2a3aeb54b5df24bc4b1f2b9d8f3742d2cdee3722f2adc`). Revisions 5 and 6 (checkers and addenda) are not edited; tests pin their hashes. r7 differs from r6 by a revision-7 note, the usage line, and two own-files entries: `P10-I-S1 ADR-0024` (`configs/p10is1_*`, `studies/p10is1/*`, `tests/test_p10is1_*`) and `P10-I-S6 ADR-0031` (`configs/p10i_s6_*`, `studies/p10i_s6/*`, `tests/test_p10i_s6_*`). No seed value, block, row, role or check of any study is altered or added; a test rebuilds r6 byte for byte from r7 by removing exactly those lines.
- **The only config change** (`configs/p10is2_partt.toml`, `[seeds]`): `registry_checker`, `registry_checker_sha256`, `registry_addendum` and `registry_addendum_sha256` now cite r7 and `SEED_REGISTRY_R7.md`. No code under `studies/p10is2/` hard-codes a hash or path of the registry files (the G9 message names the cited file from the config); the one other file touched in `studies/p10is2/` is `README_PARTT.md`, two sentences naming revision 7 (documentation, in the identity set by file hash).
- **Proof (measured, this tree).** r6: FAIL, 66 problems. r7: `RESULT: PASS`, 67 allocations, 0 problems, 314 own-files cases (R 34, S0 48, S1 24, S2 76, S3 52, S5 38, S6 42). r7 still FAILS on planted faults: a foreign value in an owned file, an owned value in a foreign file, a Part T value outside its rows (each in its own copy of the tree, and together in a test); the r7 `--selftest` still prints FAIL on its planted faults. G9 run through `run_gates` on the tiny test world with the real Part T config and the real r7 checker on this tree passes; no ledger was charged.
- **The frozen Part Q test passes again without a conftest marker.** The test's Part T half calls `gates.seed_gate("T", core.load_config("T"))`, which follows the config, so it passes with r7; a strict expected failure would turn red, so none was added. If a later merge breaks it again, the marking rule of ruling 42 applies.
- **Not changed.** No threshold, seed, cell or cap, no Part Q code, test or result, no existing ADR.
