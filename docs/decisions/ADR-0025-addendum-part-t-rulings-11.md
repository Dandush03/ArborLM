## Ruling 43: G4-MPS, the optimiser-step comparison

- **Reason.** The eighth audit (finding 3): the amendment of ruling 39 replaced the 20-update parameter comparison by gradient agreement at identical parameters, which no longer covers gradient clipping or the AdamW step on MPS.
- **What is done.** A new module `studies/p10is2/partt_mps_step.py`; `g4_mps` calls it and its result gates the gate (`passed = losses and gradients and optimiser step`). CPU and the device receive the same parameters, the same gradients (the CPU's, copied) and, where a step needs one, the same AdamW state, and take `clip_grad_norm_` plus `AdamW.step` each, for three steps: (1) fresh state, batch-0 gradient; (2) the CPU optimiser's state after step 1 copied, batch-1 gradient; (3) fresh state with the batch-0 gradient scaled to four times `clip_norm` (clipping active). The two updates (new minus old parameters) are compared tensor by tensor, relative to the step size, with the exact-zero clause (a tensor whose CPU update is exactly 0 must be exactly 0 on the device), by the existing `compare_gradients`. The result is recorded as `optimiser_step_agreement`.
- **Tolerance: none new.** The figure is `gates.mps_gradient_relative_tolerance` = 1.0e-3, the one registered for CPU/MPS agreement of the amended gate (ruling 39, `ADR-0025-addendum-part-t-g4-mps-amendment.md`; the same figure as the loss condition's `mps_loss_tolerance` it was fixed against). The superseded `mps_parameter_relative_tolerance` (1e-4, parameter-relative) is not used. The tolerance is applied to the update relative to its own norm, which is tighter than a parameter-relative figure whenever the step is smaller than a tenth of the parameter norm.
- **Failable.** Tests plant a 1 % learning rate on the device (fails, over tolerance in every step), a nonzero update on a zero-gradient tensor (fails, exact-zero clause), and, on the device, the same through `g4_mps` (gate fails with the loss and gradient conditions still passing); noise of 5e-4 passes.
- **Measured (the tiny test world, MPS, not real data):** the largest relative update difference 2.1e-7 (tensor `store.values.0`, step 2) against the 1e-3 tolerance.
- **Not changed.** The loss condition, the gradient condition, the 20 updates, M1 as the only compared cell; no label rule, cell, seed or cap. LoRA, E-table and M-ii remain not MPS-compared.

## Ruling 44: G8 is reported NOT RUN on a bundle without stored reference logits

- **Finding.** ADR-0022 section 12.3 (carried by ADR-0025 section 7.3) defines G8 in two halves: (1) the result recorded by the data-generation step is present and within tolerance; (2) the registered path's student reproduces the STORED reference logits, including the injection-point logits and greedy sequences, within the same tolerance. Part Q's step-1 record (`inputs/record.json`, key `equivalence`, listed in Part Q's plan reuse hashes and so readable through the checked door) holds only the verdicts of half (1) for read layers 4 and 12 (`ok`, `max_abs_difference`, `identical_top1`). The reference arrays half (2) needs are not stored (`equivalence_layers` is absent from the bundle's `extra`). So **G8 as the ADR defines it cannot be run on the real Part Q bundle** by reading its record.
- **What is done.** G8 reports **NOT RUN**: `passed` None, `not_run` True, never a pass; the gates record of every stage lists `not_run: ["G8"]` beside `skipped`; half (1)'s recorded verdicts are echoed through the door (`studies/p10is2/partt_g8.py`, never recomputed, no threshold applied beyond Part Q's recorded `ok` flags), together with the statement that half (2) is absent. With stored records (a stand-in bundle) the full test (`equivalence.verify_all`) runs as before.
- **Left for the lead's ruling.** Whether the gates stage may pass with G8 NOT RUN (it does today: `run_gates` fails only on `passed is False`, and `status` stays `PASSED`), whether Part Q's step-1 `ok` verdicts plus the hash-checked student bytes are accepted as covering G8, or whether the reference arrays must be regenerated (a heavy step this implementation does not take). **PENDING LEAD REVIEW** before the freeze. Nothing sealed (`qfit/`, `qcheck/`, `generation/`, `sealed/`) was opened.
