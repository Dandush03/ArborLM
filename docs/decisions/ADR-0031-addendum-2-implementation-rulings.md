# ADR-0031 addendum 2 — further rulings for the implementation of P10-I-S6 (2026-11-19)

Rulings of the scientific lead (Claude Fable 5.2) after the second implementation audit (`docs/reviews/p10-i-s6-implementation-audit-2026-11-19/AUDIT2_P10IS6.md`, arbor-auditor subagent, Claude Opus 5.5; verdict READY AFTER LISTED FIXES at commit `1dce8a2`). As with the first addendum: made before any registered or calibration value of this study exists (no parent trained, nothing downloaded, no rehearsal run); no threshold changes; put to the human lead for confirmation with the run decision. Neither ADR-0031 nor the first addendum is edited. `Astra review: NOT_PERFORMED`. Claude review is not Astra review.

16. **Ruling 4 of the first addendum is corrected: its excluded set was too small.** It rested on the first audit's statement that excluding the shared panel ledger's spans and P10-I-S3's two panels equals "continuing after" P10-I-S3's panels. The second audit tested that on the real files and withdrew it: with that set, 153 of the 1,024 new panel chunks overlap windows that P10-I-S3 had excluded (P10-S2's generation windows), 87 of them inside P10-I-S3's rank range. The excluded set of the panel walk is therefore: every span of the shared panel ledger (`data/p10i-shared/panel_ledger.json`), P10-I-S3's two panels, AND every span of P10-I-S3's own excluded set (`excluded_spans.json` of its data directory, recorded SHA-256 beginning `40e63363`), which the audit shows gives 0 overlaps. That file is a frozen input of the data command, by hash. The walk still starts at rank 8,192. The rest of ruling 4 (article numbering) stands. Direction: neutral; it was an error of the lead's ruling and of the audit it relied on, found before any data was prepared.
17. **The shared panel ledger is read and appended in its real format.** The data command reads the ledger as it is on disk, never assumes keys, and appends this study's two panels without rewriting any existing key or entry (the ledger's hash before and after, and the entries added, are recorded). A failure of the data command leaves nothing behind that makes a rerun refuse; a partial output is kept aside, not deleted.
18. **The measuring rehearsal's probes are long enough to measure a rate.** A probe trains at least 2,048 updates, so that the per-update rate is not swamped by the process overhead; a negative or non-finite rate is an engineering stop of the rehearsal, never a figure the caps use. The freeze ties the plan's unit costs, and so the caps, to the measuring rehearsal's record by its SHA-256 and refuses a difference.
19. **Everything that produces a number is in the computing list.** The files that compute BASE values, panel slices, calibration curves, the data tables and the parents (`stages.py`, `rehearsal.py`, `d0.py`, `p0.py` as far as they compute) are in the list whose identity binds results, or their computing parts are moved into files that are; the orchestration list holds only code that cannot change a number.
20. **Sealed values are never written inside a git working tree.** The rehearsals check that the sealed directory is outside every git working tree BEFORE writing anything into it, and refuse otherwise.
21. **A failed run that also shows an integrity break** is read as row 1 (NOT EVALUABLE, the integrity cause), as section 12.2's order gives; the audit notes that either row is against the memory. (Completes ruling 10.)
22. **The pin step checks completeness.** The shard list is complete (`train-0000i-of-0000N` for every i from 0 to N−1) or the pin refuses. Before the download the lead verifies by hand, at the Hub, the repository `Salesforce/wikitext`, revision `b08601e04326c79dfdd32d625aee71d232d685c3`, configuration `wikitext-103-raw-v1`, the shard names, sizes and SHA-256 values against what the pin step wrote, and records them in the download ledger rows before fetching.
