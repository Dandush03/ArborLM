# ADR-0025 addendum: Part T rulings 31 to 33 (sixth addendum)

Status: rulings of the lead coordinator after the fifth check of a32afc6 (C1', C2', C3'). They bind like the ADR and the earlier addenda (none is edited). Recorded by the implementer from the coordinator's message; not a human-lead approval record beyond what the coordinator states. `Astra review: NOT_PERFORMED`.

31. **The session hashes cover everything that can change a calibration value (C1').** The identity each session's start line carries is the Part T frozen set (every `studies/p10is2` file outside `partq/` and `freeze/`, the Part T config, `uv.lock`, `pyproject.toml`) plus the import-walk closure of the Part T entry modules (`plan.import_walk`, the function the freeze uses for the registered stages: `studies/p10s2`, `src/arborlm` and anything else the modules import from the repository) plus `configs/p10s2_transfer.toml`. A resume under any other hash is refused; the final record carries the identity it was computed under and it must equal every session's.
32. **`calibrate` commits its own log lines (C2'; favours the memory).** After each finished unit, each stop, each INTERRUPTED line (and the resumed start and the end line) `calibrate` appends the line and makes a signed single-line commit of the log file alone: `P10-I-S2 Part T: calibration log <session> <event> [skip ci]`, no trailers, `git commit -S`, never `--no-verify`. If the commit fails the session stops PAUSED before the next unit and nothing is redrawn; the pending lines are committed first on the resume. A unit's state file is accepted on resume only if a committed `unit` line carries its SHA-256; a state file without one is kept aside under `state/attempts/` and the unit is NOT rerun silently: the run stops until a committed `results/p10is2-partt-calibration/UNIT_DECISION.md` names it (`unit: <id>`), the lead's recorded decision. `calibrate` (run) refuses unless the commit holding the open line is contained in a remote-tracking branch (`git branch -r --contains`, no network call): the lead pushes it before the run. **Residual, stated:** a force-push over the pushed history; the repository's history (the reflog of the remote, the signed commits' dates) would show it.
33. **The budget bound is the human lead's to set (C3').** While `caps.study_budget_hours` is 0.0 or absent, `caps-config`, `candidate-plan` and `freeze` REFUSE: the bound is the human lead's to set and is recorded in the rulings before the plan. When set, each of the three checks the proposed total against it.
