### `classes.py`

- `mc_pair` / `match_snapshot` (ADR §5.4, review M7): when the two measures disagree on the costlier cell, read the pair in the comparator's favour. The caller states which cell's advantage would be claimed (the larger cell on the capacity line; the memory arm in the dense labels). That cell is read at U_P; the other at the smallest grid snapshot with multiplier ≥ max(r, 1/r) over both measures; status OK with the annotation MC-AMBIGUOUS; MC-SHORT if that snapshot exceeds the other cell's run length. Equal costs (|r − 1| ≤ EPS in both measures) are not a disagreement.

## 5. Tests that must exist

1. **Registry:** 31 / 155 / 70; the cells of every arm; 30 / 150 without 2K/256; no 65,536-slot cell constructible in registered mode; T-OQ, H8, D-OQ and the index read refused at 256 slots.
2. **Plateau floor:** on the revision-4 calibration curves (copied into a fixture as numbers, not read from `results/`), no cell is loaded at 1,024–8,192 updates; a flat cell below the floor prints FLAT BELOW THE DEP FLOOR.
3. **Load search:** a first pass alone gives no U_L; two consecutive passes give the second; pass–fail–pass–pass gives the last; a view above 4.0 gives none; a failed run and a capped run give none; each fixed outcome, the 2K/256 outcome included.
4. **Row U_P:** each candidate selected; none qualifies → return.
5. **Dense rate:** plain maximum; ties and the walk; diverged rates; all diverged → return; 0.1 ahead by more than 0.02 → return; 0.1 by the walk → EDGE BY TIE-WALK.
6. **Matched compute:** agreeing measures as before; a disagreement read in the comparator's favour in both uses (capacity step; dense label), with the annotation; MC-SHORT when the snapshot exceeds the run length; equal CPU cost is not a disagreement. **No fixture may set the 1,024-slot cost equal to the 4,096-slot cost** (review m10).
7. **Dense at saturation:** each label and sub-label; the path DENSE HOLDS MORE → DENSE AHEAD → CAPACITY-NEGATIVE (b); the cost condition; D-OQ not plateaued by gain and by floor.
8. **Saturation line:** every pair verdict, pair class, arm class (DEPENDENCE_FAILED included) and outcome; F-OQ with two pairs, the other arms with one; 2K/256 absent; ρ exactly 3.0; the printed phrases.
9. **Capacity and efficiency lines on the new steps:** every verdict and class of §8.2–§8.4 and §8.8 on synthetic records; the 0.80 floor at 32K/16K; efficiency ignores C1 and C2; the synthetic scenarios of §10.2 that must give INCONCLUSIVE and never NEGATIVE.
10. **Milestone reading:** each of the readings; "storage half supported" refused without the saturation class, with DENSE HOLDS MORE, or with an unestablished matched-compute reading.
11. **Labels:** every positive label carries the tag; H8 NOT CALIBRATED AT cell; "16,384→65,536 NOT TESTED"; "SIZES 1,024–16,384".
12. **Budget:** c never below 1.0; longest-first packing; the cap rule; the three cuts in order; NOT STARTED: BUDGET above 36.
13. **Guards:** the concurrency refusal; registered-mode refusals; G9 with 2193 and its derived seeds.
14. **Config:** the generated TOML equals `core`; `[thresholds]` equals revision 4's values, one by one.
15. **End to end** on test seeds: preview → calibration → finalize → rehearsal → project → freeze → the registered sequence under the test-only switch.

## 6. Places where the specification may still not be implementable one way

Report each to the lead before coding it; the suggestion is the drafting context's and is not a ruling.

1. **Item caps when items share the six workers.** The ADR gives each item a cap of twice its projected wall time at six workers, and runs 0b with 1, and 2 with 3. Suggested: one cap per pooled step.
2. **The isolated rate in c.** The ADR says §10.2's isolated rates; the calibration's rates exist before the rehearsal. Suggested: compute c at `project`, from §10.2's isolated wall seconds per update and the calibration's training wall seconds per update, matched by arm and slot count.
3. **"Diverged" by the chance interval.** The readout is a_use; the G2 interval is on raw correct counts. Suggested: raw Panel A correct count inside the interval at the readout, on either draw.
4. **What counts as another study running.** Suggested: any live worker process of `studies.p9ii`, `studies.p10s0` or `studies.p10s2`, checked by command line, in addition to the load-average rule of §7.5. The S0 "registered run in progress" test needs a marker the lead names (S0's run directory or ledger).
5. **2K/256 with no U_L.** The ADR (§25.11 item 4) says the cell is then not run. If the lead strikes that, the cell needs a run length.
6. **F-OQ's saturation class when 2K/256 is NOT FULL and 1,024 → 4,096 is PROPORTIONAL.** By the table it is INTERMEDIATE, so F-OQ cannot carry SATURATION-PROPORTIONAL, though T-OQ or F-OQ-IVF can. Implement the table; this is listed so that nobody "fixes" it.
