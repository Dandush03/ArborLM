## 7. Dry failure (point 10): C1 a3 alias run for `C1.while_counter_f3`

The text I read: `experiments/_scratch/m0_fr_dry_c1_20261126/attempt1/C1{a,c}/dry/a3/run_log.json`, the fields `alias_rc`, `alias_err`, `own_rc` and `own_err` only, plus every `*stderr*` file under `attempt1/`. Every other lineage has rc 0. `alias_err` ends with `concurrent/futures/_base.py … raise self._exception` and `AttributeError: 'NoneType' object has no attribute 'group'`. The stored text is truncated by the wrapper and **does not itself name `a3_shortcuts.py` or a line**.

- **Is it the script's own code?** Yes. From the code: `a3_shortcuts.py` (committed, run as committed, given the relabelled draw by the committed wrapper's `A3_ALIAS`/`A3_OLD`) parses each item in `process_file` → `item_record` → `specific` inside its `ProcessPoolExecutor`. The own-id rerun of the same items passes through all the same code except the `lid == "C1.while_counter"` branch, and it exited 0. So the exception is in that branch, at one of its `re.search(...).group(1)` calls (lines 221, 222, 227 and 229 at `b78e58b1`): the audit-3 parser's regex does not match a fix-3 `while_counter` program. No copy and no plan setting is involved: there is no copy on this path, and `--gen`, `--a3` and `--out` worked for 25 other lineages.
- **Does it depend on the item count?** No. It is a per-item parse failure on one program, not a statistic taken over an empty group. Both draws are prefix-stable: `c1_fix4_draw` and `f1_draw` build items one after another from `rng_for(seed, lid, level)`, so the first 20 items per level at `--per-level 2000` are the 20 items of the dry draw. On the dry seed, at the plan's count, the same item occurs and the alias run fails in the same way. On the run seeds, a failure is at least as likely with 2,000 items per level.
- **What follows from the text.** Nothing is excluded. The unit did not fail: the committed wrappers catch a non-zero alias exit and rerun under the draw's own id. Both headers state this behaviour ("the draw is run again under its own id (generic rules only) and the failure is recorded"), and both runs here ended with own rc 0. Point 10's exclusion applies only to "a unit whose own code cannot execute", which is not the case here. Point 11's report lists "every lineage and seed for which an a3 wrapper's alias run failed and it fell back to its generic rules, which lowers that lineage's specific-rule figures mechanically (check 6, K18)". **The lead's reading is confirmed:** no unit or lineage is excluded, the fallback is the scripts' own committed behaviour, and each occurrence (per lineage and seed, C1a and C1c separately) goes into point 11's report.
