## 1. What is known, and what is only suspected

Registered (P9-I, one data draw, two initialization seeds, U = 8,192 updates):

- Oracle-query retrieval (R1) 0.967–1.000 and oracle address (R2) 1.000: the memory stores and returns answers when addressed.
- The natural query, the seven-position window query (W7), its embedding version and a four-head attention query: 0.028–0.044 at every size (chance about 0.03).
- The dense adapter on the same window (D7): 0.78–0.80 at 16,384 slots (0.44 on the second backbone), 0.13 at 65,536. The window carries the identity.
- Training the block-0 attention: partial at 4,096 slots (0.54–0.65), with next-byte loss up 67–100%.

Exploratory (the review's diagnostics; other draws, not registered):

- In every run the queries collapse within 64 updates (mean cosine between queries of different facts 0.95–0.998; 1–6 distinct top-1 slots); the loss then sits at ln 32, the answer-symbol marginal.
- 91–99% of the trained pre-normalization query is the same vector for every fact (0.50–0.57 at initialization): the separator, binding byte and position components shared by every record.
- In the collapsed state the gradient on the query projection is about 2.7e-6 against 1.9e-2 on the output projection.
- W7 at 4,096 slots later escaped and reached 0.94–0.98 in 9 of 11 runs on five other draws; on the registered draw it had not. At 16,384 slots it reached only 0.04 by 8,192 updates on two draws.

So the leading hypothesis is unstable optimization of sparse addressing, not missing information and not insufficient storage. That hypothesis has not been tested by a registered experiment. This study tests it.

## 2. Question and hypotheses

**Can a learned query–key interface be trained to give distinct, useful addresses through sparse top-8 retrieval, reliably across independently generated data draws and initialization seeds, and at more than one memory size?**

- **H19-A (collapse under the answer-only objective).** With answer-only training, the queries of W7 collapse early (mean cosine ≥ 0.9 within 256 updates) in most cells, and the arm is not reliable across draws.
- **H19-B (addressing supervision).** An auxiliary objective that tells each query which key it should match prevents or reverses the collapse and makes the arm reliable.
- **H19-C (staged optimization).** Learning addresses first and answers second is at least as reliable as learning them jointly, and the addresses survive the removal of the supervision.
- **H19-D (curriculum).** Starting from a dense, differentiable read and annealing to hard top-8 makes answer-only training reliable without any fact identity.
- **H19-F (common mode; added by the lead).** Removing the fact-independent component of the query before normalization, with a diversity penalty, makes answer-only training reliable without any fact identity.
- **H19-E (draw robustness).** A reliable arm succeeds in every draw, not only on favourable ones.

Each can fail. If no learned arm is reliable at 4,096 slots, the result is a registered negative on trainable sparse addressing for this interface and backbone, and the recommendation is a different retrieval architecture, not more compute.

## 3. System common to all arms

- Frozen 27,392-parameter backbone, the P9-I task (ADR-0017 §4), the flat memory of ADR-0017 §5 (cosine keys, key width 16, top-8, read temperature 0.2), read and added **at answer sites only**, alphabet-only loss, one AdamW (lr 0.003), batch as P9-I. **No backbone parameter is trained in any arm**, so the pretrained language model is unchanged by construction; gate G5 (§9) checks that the logits on corpus rows are bit-identical to the frozen backbone's.
- Query before normalization: z = W·[h_{t−6}; …; h_t] (the W7 form of P9-I), q = z / ‖z‖. Key k_s for slot s, κ_s = k_s / ‖k_s‖. Score a_s = q·κ_s.
- **No fact identity is an input of any learned arm at inference.** The forward of arms A0–A5 takes tokens only; a test asserts that the function has no identifier argument and that changing the fact table does not change its output. Fact identities used in training are listed per arm in §4 as auxiliary supervision.
- Every cell runs exactly U updates in total (§6), whatever its stages.

## 4. Arms

| Arm | Mechanism | Fact identity used in training | Extra trained parameters |
|---|---|---|---|
| A0 | W7, answer-only (the P9-I arm, unchanged) | none | — |
| A1 | A0 + address loss L_addr with constant weight λ for all U updates | target slot of each fact | none |
| A2 | Stage 1: L_addr only, for U_pre updates (query projection and keys train; values, output projection and gate frozen). Stage 2: answer loss only for U − U_pre updates, everything trainable, **L_addr removed** | target slot, stage 1 only | none |
| A3 | Answer loss + λ(t)·L_addr from the first update; λ(t) falls linearly from λ to 0 at update U/2 and is 0 afterwards | target slot, first half only | none |
| A4 | Answer-only. The read uses **all** slots with weights softmax(a/τ(t)); τ(t) falls geometrically from τ_0 to 0.2 at update U/2; from U/2 the read is the standard top-8 at 0.2 | none | none |
| A5 | Answer-only + centred queries: z′ = z − m, with m an exponential moving average of the batch mean of z (decay 0.99, no gradient through m), q = z′/‖z′‖; plus a diversity penalty μ·L_div on the batch's queries | none | none (m is a buffer) |
| A1-S | Negative control of A1: the target slot is redrawn uniformly at random for every occurrence (not a function of the fact) | a random slot | none |
| A6 | R1, the oracle-query reference (ADR-0017 §5.3) | oracle at inference (reference only) | — |
| A7 | D7, the parameter-matched dense window control | none | — |

Definitions.

- **Target slot.** A fixed injection s(f) from the trained facts into the N slots, drawn once per cell from a seed (§7). It is an arbitrary label, not an oracle code: nothing about s(f) is visible in the tokens.
- **Address loss.** For an answer site of fact f, L_addr = −log( exp(a_{s(f)}/τ_a) / Σ_{s=1..N} exp(a_s/τ_a) ), averaged over the batch's answer sites, τ_a = 0.2. It has gradients to W and to the keys only.
- **Diversity penalty** (A5). With q_1…q_B the centred, normalized queries of a batch, L_div = log( mean_{i≠j} exp(2·q_i·q_j) ). It is minimized by spread-out queries and uses no fact identity. Because it would also separate two occurrences of the same fact, §8 measures same-fact consistency for A5.
- **A2's stage 1 and the budget.** U_pre counts inside U. No arm gets more updates than another.
- **Hyperparameters fixed by calibration** (§6), one per arm: λ for A1 and A3, U_pre for A2, τ_0 for A4, μ for A5.

**What each contrast tests.** A0 against A1: does address supervision prevent collapse (H19-B). A1 against A2 and A3: what happens when the supervision is removed (H19-C, mandatory control 3). A0 against A4: does a soft-to-hard curriculum suffice without labels (H19-D). A0 against A5: is the common mode the cause (H19-F). A1 against A1-S: does the address loss work because it is fact-specific, or because any extra gradient on the keys helps (mandatory control 9). A6 and A7: ceilings and the dense alternative on the same draws.

## 5. Stages, draws and seeds

| Stage | Size (slots / facts) | Arms | Draws × init seeds | Updates | Cells |
|---|---|---|---|---|---|
| 1 | 4,096 / 2,048 | A0, A1, A2, A3, A4, A5, A1-S | 8 × 2 | U | 112 |
| 1 | 4,096 / 2,048 | A6, A7 | 8 × 1 | U | 16 |
| 2 | 16,384 / 8,192 | A0, the arms that pass the Stage 1 gate (at most 3, by the precedence of §8.4), A6, A7 | 4 × 2 (A6, A7: 4 × 1) | 4U, read at U and 4U | at most 40 |
| 3 | 65,536 / 32,768 | A0, the single selected arm, A6, A7 | 2 × 1 | U | 8 |

- **Draws.** Eight new registered data draws, generated from eight new seed sets (§7). Each draw is a complete, independent data set: facts, clusters, templates, training stream, Panels A and B, held-out template panels, unseen-fact control. Stage 2 uses draws 1–4 and Stage 3 draws 1–2, regenerated at the larger fact counts from the same seed sets. The P9-I registered draw and all rehearsal draws are historical only and enter no rule.
- **Pairing.** Within a draw and seed, every arm sees the same data, the same batch order and the same initialization of the shared parameters.
- **Why 8 × 2.** Sixteen cells per arm let the study separate between-draw from within-draw variation and estimate a failure rate. With 15 or 16 successes of 16, the one-sided 95% lower bound on the success probability is 0.74 or 0.83. The study does not claim more than that.
- **Stage 2 runs 4U updates** so that one training gives both readouts: at U (matched updates with Stage 1) and at 4U (matched exposures per fact with Stage 1: 512). Every rule states which readout it uses.
- **Stage 3 runs U updates only** (32 exposures per fact). A matched-exposure run at that size does not fit the budget. Stage 3 is therefore a probe, and can produce only the labels of §8.5.

## 6. Budget of updates and calibration

- **U = 8,192**, the value calibrated and audited in P9-I for the oracle rungs. It is not re-tuned.
- **Calibration** (before the freeze, designated calibration draws only): at 4,096 slots, two calibration draws (rehearsal seed sets 3 and 4, which nothing has used), one initialization seed, each arm at each value of its grid:

  | Arm | Grid |
  |---|---|
  | A1 | λ ∈ {0.1, 1.0} |
  | A2 | U_pre ∈ {1,024, 2,048} |
  | A3 | λ ∈ {0.1, 1.0} |
  | A4 | τ_0 ∈ {1.0, 5.0} |
  | A5 | μ ∈ {0.1, 1.0} |

  Rule: the value with the higher minimum Panel A accuracy over the two draws; a tie, or a difference below 0.02, goes to the first value listed. 20 cells. A0, A6 and A7 are run on the same two draws as a check of the pipeline (3 × 2 cells). Nothing else may be changed after calibration.
- Calibration accuracies are reported as calibration, never as results.

## 7. Seeds and data identities

- Registered data seed sets: `p9ii-draw-1` … `p9ii-draw-8`, base seeds 190001, 190101, …, 190701 (each set uses base + i as P9's generator does). Initialization seeds 1901 and 1902. Target-slot seeds: derived from the draw base and the initialization seed.
- Calibration: rehearsal seed sets 3 and 4 of the P9 namespace (179301+, 179401+), initialization seed 1891. Rehearsal for time and memory: rehearsal seed set 5. Tests: 900001 upward.
- The implementation asserts that the registered, calibration, rehearsal and test seed ranges are disjoint from each other and from every seed used by P9 and P9-I, and writes the hash of every stream to a data manifest at freeze time.
- Within a draw, training contexts, Panel A, Panel B and the held-out template panels are disjoint as in ADR-0017 §4. No registered panel is used for calibration or selection.

## 8. Measurements, classes and rules

### 8.1 Recorded during training (every 64 updates, on a fixed probe set of 512 Panel A answer sites of that draw; no gradient)

Mean cosine between queries of different facts; effective rank and total variance of the centred queries; number of distinct top-1 slots and the largest top-1 share; share of facts with a private slot (in the top 8 of exactly one probe fact); for arms with a target slot, top-1 and top-8 recall of s(f) and the mean score a_{s(f)}; mean cosine between each query and its top-1 key; gradient norms and actual parameter movement since the previous record for the query projection, keys, values and output projection; the answer loss and, where present, L_addr and L_div; the fact-independent share of E‖z‖².

- **Collapse onset:** the first record at which the mean query cosine is ≥ 0.9.
- **Escape:** the first later record at which it is ≤ 0.5 and stays ≤ 0.5 to the end.
- A cell is **never collapsed**, **collapsed and recovered**, or **collapsed and not recovered**. These are reported for every cell and are not merged.

### 8.2 Recorded at the readout (U; also 4U in Stage 2)

Accuracy on Panels A and B and on the held-out template panels H1/H2; negative log-likelihood over the alphabet; accuracy with the memory disabled and with values permuted; unseen-fact control with the LEAKAGE flag; gate G2 (chance interval) on the no-memory backbone; address stability (share of facts whose top-1 slot is the same on Panels A and B); same-fact consistency (mean cosine between the Panel A and Panel B queries of the same fact); distinct selected slots; CPU seconds, peak memory, and active retrieval work (key scores computed and value rows read per query; A4's dense phase is reported separately).

### 8.3 Cell success

A cell of a learned arm **succeeds** at a readout if, on both Panels A and B:

1. accuracy ≥ 0.90 × the accuracy of A6 on the same draw and size (and A6 ≥ 0.90, else the draw is NOT_EVALUATED at that size);
2. accuracy with values permuted and with the memory disabled is inside the G2 interval;
3. mean query cosine at the readout ≤ 0.5;
4. accuracy on H1 and H2 ≥ 0.90 × the cell's own Panel A accuracy (the address generalizes to held-out contexts).

### 8.4 Arm class at a size (learned arms A0–A5 and A1-S; first match wins)

| Order | Class | Rule |
|---|---|---|
| 1 | NOT_EVALUATED | more than one draw is NOT_EVALUATED at that size |
| 2 | RELIABLE | at least 15 of 16 cells succeed at Stage 1 (at least 7 of 8 at Stage 2) and every evaluated draw has at least one success |
| 3 | UNRELIABLE | at least 4 of 16 succeed (at least 2 of 8), not row 2 |
| 4 | FAILS | otherwise |

- **Stage 1 gate.** An arm goes to Stage 2 only if it is RELIABLE at Stage 1. If more than three are, the three are taken in this order of preference: A5, A4 (no fact identity in training), then A2, A3 (supervision removed), then A1. A1-S never advances.
- **Stage 2 class** is decided twice, at U and at 4U, and both are printed. "RELIABLE at 16,384" without qualification means at 4U (matched exposures); RELIABLE at U as well is printed as **ALSO AT MATCHED UPDATES**.
- **Annotations per arm and size:** the count of never-collapsed, recovered and not-recovered cells; median escape update; **SUPERVISION-DEPENDENT** for A2 or A3 if top-8 recall of s(f) falls by more than 0.10 between the removal of L_addr and the readout in more than half of the cells; **NEGATIVE CONTROL FAILED** if A1-S is RELIABLE or UNRELIABLE (then A1–A3's classes are printed but not interpreted as fact-specific supervision); **DENSE COMPARISON** per size as BEATS DENSE (median over draws of accuracy(arm)/accuracy(A7) ≥ 1.10) or DENSE SUFFICES otherwise, compared only for RELIABLE arms.

### 8.5 Stage 3 (probe)

Runs only if an arm is RELIABLE at 16,384 and the charged time left is at least twice the rehearsed Stage 3 projection. The selected arm is the first RELIABLE arm in the preference order of §8.4. Its label is **SCALE PROBE POSITIVE** if both cells succeed, **SCALE PROBE NEGATIVE** if neither does, **SCALE PROBE MIXED** otherwise. With 32 exposures per fact a negative is exposure-limited and is not evidence against scaling.

### 8.6 Study outcome (first match wins)

| Order | Outcome | Rule |
|---|---|---|
| 1 | ENGINEERING_FAIL / INCOMPLETE / NOT_INTERPRETED | as ADR-0017 §8.6 and §I.9: a G4 defect; missing or failed cells; a failed gate |
| 2 | INCONCLUSIVE | Stage 1 is NOT_EVALUATED, or NEGATIVE CONTROL FAILED and no label-free arm (A4, A5) is RELIABLE |
| 3 | ADDRESSING-RELIABLE | some learned arm other than A1-S is RELIABLE at 4,096 and at 16,384 (4U) |
| 4 | ADDRESSING-RELIABLE AT 4,096 ONLY | some learned arm is RELIABLE at 4,096, none at 16,384 |
| 5 | ADDRESSING-UNRELIABLE | no learned arm is RELIABLE at 4,096, at least one is UNRELIABLE |
| 6 | ADDRESSING-FAILS | every learned arm FAILS at 4,096 |

- **Hypothesis readings, fixed now.** H19-A is supported if A0 has collapse onset within 256 updates in at least 12 of 16 cells and is not RELIABLE. H19-B: A1 RELIABLE and A1-S not. H19-C: A2 or A3 RELIABLE without SUPERVISION-DEPENDENT. H19-D: A4 RELIABLE. H19-F: A5 RELIABLE. H19-E: any RELIABLE class.
- **The interface carried forward** is the first RELIABLE arm at 16,384 in the preference order, with all its annotations. If the outcome is rows 5 or 6, the recommendation is to change the retrieval architecture.

## 9. Gates

- G1 (generator, per draw), G2 (chance, per draw and size), G4 (determinism, checkpoint restoration, gradient reach for every arm on contexts the cell covers; the address loss reaches the query projection and keys and nothing else; A5's centring buffer receives no gradient; A0's forward and one training step are bit-identical to P9-I's W7).
- **G5:** on the backbone's corpus rows, every arm's logits equal the frozen backbone's bit for bit.
- **G6:** the forward of arms A0–A5 and A1-S has no fact-identity input; evaluation under a permuted fact table gives identical outputs.
- The gates stage runs on rehearsal seeds before the freeze and again on registered seeds before training; a failed gate stops the run.

## 10. Resources (projection from P9-I's rehearsal; the rehearsal of this study fixes the caps)

- Measured in P9-I with six workers: 0.008–0.012 s per update at 4,096 slots, 0.013–0.015 at 16,384, 0.035–0.049 at 65,536; peak worker memory 1.49 GiB.
- Projection: calibration 26 cells ≈ 0.6 hours summed; Stage 1 128 cells ≈ 2.9 hours summed; Stage 2 at most 40 cells of 4U ≈ 5.1 hours summed; Stage 3 8 cells ≈ 0.8 hours summed. With six single-thread workers: about 0.1 + 0.5 + 0.9 + 0.15 hours, plus evaluation. A4's dense phase and the per-64-update probes add cost that the rehearsal measures.
- **Caps:** 3 GiB per worker; 24 GiB aggregate; **4 hours of charged execution for calibration, rehearsal and the registered stages together**; the rehearsal must show at least 2× headroom on time and memory for each stage, or the stage is cut by the rule fixed here (Stage 3 is dropped first; then Stage 2 is run on draws 1–2 only) and that is recorded before the freeze. No timing-sensitive comparison is made between cells; CPU seconds are reported descriptively.
- No cloud, no downloads, no new dependency, no SSD work.

## 13. What this study cannot establish

- Anything about memory capacity, useful-capacity scaling, locality or incremental learning. More slots in use is not more capacity.
- That a reliable arm would be reliable on natural language, on another backbone, with another interface than W7, or at 65,536 slots (Stage 3 is a probe at 32 exposures per fact).
- That address supervision is available in a real system: a target slot per fact is a training label this task provides.
- That W7 is a general interface: it is told the record length.
- A success probability above the bounds stated in §5.
- A failure of the ArborLM concept, whatever the outcome.
