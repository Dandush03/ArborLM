B. AMBIGUOUS ITEMS (keys depend on a reading)
B1 slot_permutations, LEADING ZERO: when 0 is among the digits and no "may not start with 0" rule is stated (20% of items that contain 0),
   the key counts strings that start with 0 as "s-digit numbers". Under the ordinary definition an s-digit number never starts with 0, so the
   key is WRONG under that reading. Fixture ids (13/140): 0/13, 0/18, 1/7, 1/9, 2/18, 3/7, 3/10, 4/2, 4/14, 4/18, 5/10, 6/4, 6/16
   (e.g. 0/13 key 405, ordinary reading 360). Generated items: 9-13.5% of items per level (always_no_leading_zero matches the key in 0.865-0.911).
   Fix: always state the rule either way ("the number may start with 0" or not), or never draw lead=False when 0 is present.
B2 last_digit_power, GLOSS: "(the power means 23 multiplied by itself 295 times)" read literally is 23^296 ("multiplied by itself once" = 23^2).
   Under that reading 116/140 fixture keys change. The phrase "raised to the power 295" is unambiguous; the gloss contradicts it on a literal
   reading. Fix: "a product of 295 factors, each equal to 23" (the wording R2.modular_power already uses).
B3 digit_puzzle, REVERSAL WITH A TRAILING ZERO: 7/140 fixture items have an answer ending in 0 with a reversal clue (1/12, 2/15, 4/15, 4/17,
   6/5, 6/9, 6/19): "reversing 980 gives a number 891 less" needs the reader to accept 089 = 89 as "a number". Minor; state it once
   ("a reversed number may start with 0; 089 means 89") or exclude such secrets.
Not ambiguities (probed and rejected): binomial "exactly j women" / "must be on it" (alternative readings contradict the text);
   division_counting "both included" (stated); median two-middle rule (stated); mode ties (excluded and stated); tiered units mode (rates > 0, unique).
