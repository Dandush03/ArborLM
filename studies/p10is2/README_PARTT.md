# Part T (the transfer itself): the run sheet, from calibration to the report

Self-check by the implementer, not independent review; not Astra review; nothing here is a result, and ArborLM is unproven research. Durations are **hypothetical** (analytical, from P10-S2's measured 0.089 s per greedy item and ADR-0025 section 14's unit counts: 54 trained cells, 66 units of U, 36 calibration units of 2,000, about 219,200 greedy items per scoring pass) unless marked; the real durations come from the measuring rehearsal. **Nothing in Part T has ever run on real data.** Everything below marked "exercised at test size" ran on a tiny synthetic world through the real launch scripts (see the last section).

Variables: `REPO` (the worktree holding the frozen code), `EXP=/Users/daniellaloush/dandush03/ArborLM/experiments`, `Q="uv run --locked --offline python -m studies.p10is2.partt_stages"`, `PQ=$EXP/P10IS2-Q-registered3-20261119` (Part Q's run directory of record, read-only), `PQPLAN` (Part Q's attempt-3 plan file, whose reuse list holds the hashes of the reused stages' files). Part T uses the lock alone (no `PYTHONPATH`). Every run directory is git-ignored or outside the repository. Nothing is written into a run directory by anything but the commands below; no `/tmp`.

## Rules every step follows

- **One mode per run directory** (`run_mode.json`: `registered`, `rehearsal` or `calibration`). A rehearsal or calibration refuses the plan's registered run directory; a registered stage refuses a directory of another mode.
- **No record is overwritten.** A calibration run again needs `--reason` and writes `calibration_<n>.attempt<k>.json` beside the old one; every recomputation attempt is kept (`recomputation/attempt_<n>.json`) and a failed one stands until `recomputation_lead_record.json` names the cause; a rehearsal's record is written once.
- **Exit codes** of every entry point: 0 done; 2 refused (a precondition; nothing written); 3 returned to the lead (PENDING LEAD REVIEW); 4 the stage did not complete (PAUSED or a task failed: read its manifest); 5 ENGINEERING STOP — RECOMPUTATION; 74 (a worker only) the rehearsal's forced pause; **75 PAUSED — IDENTITY** (a frozen file, the config, the plan, a manifest or a Part Q file differs; nothing is written; restoring it bit for bit and running the same command resumes).
- **Pause and resume.** A stage stopped by its cap, a memory guard or an identity difference is PAUSED, never failed: run the SAME command again. Completed tasks (their `*.result.json`) are not run again; a task that failed keeps its failed record and an item error (the analysis refuses while one stands) and is released for ONE resume only by `$Q retry --stage S --task-id T --run-dir D --cause "<recorded cause>"` when the fix changes no frozen file; a non-finite cell is never released.
- **Caps.** A cap of 0 is never "uncapped". The caps are computed by code from the measuring record (below) and are `charge before the freeze + 2 x projected` in total and `2 x projected` per stage.
- **Seeds.** Registry revision 5 (`docs/reviews/p10-i-direction-2026-11-17/SEED_REGISTRY_R5.md`): the rehearsal training draw is seed 252002; test-mode initialisation 330281-330296; gate G5's probe 250919. Gate G9 runs the revision-5 checker unedited and requires `RESULT: PASS`.
- **The machine is shared.** At most 3 workers (2 while another study runs), 8 GiB per worker. Only the timing benchmark needs a quiet machine (no study process of any study alive, load at most 2.0 for 60 s before each repetition). Every launch script starts `caffeinate -i -w <its own pid>`, which ends with the stage; it is the stage's own process family and is never counted as another study (`procs.is_keep_awake`).

## The sequence

Order (ADR-0025 sections 7.1 and 10 as written, rulings 21 and 22): **measuring rehearsal -> the cap for calibration -> calibration -> candidate plan -> registered caps -> plan again -> counting rehearsal -> freeze -> Decision 2 -> registered stages.** Each step: the command, what it prints or writes, and the condition that must hold before the next.

1. **Measuring rehearsal** (hours on real data; MPS training, CPU scoring; only when the lead says so; it needs NO calibration result). `cd "$REPO" && sh studies/p10is2/launch/partt_rehearse.sh measuring "$EXP/P10IS2-T-measuring-<date>" --part-q-dir "$PQ" --part-q-plan "$PQPLAN"`. The config must still hold the registered caps unset.
   - It trains **200 updates** of every trained cell type (`[rehearsal] updates` in the config; the starting rates and the read layer of the grid are its stand-in calibration block) and builds its own plan from the config. It drives `partt_registered.sh <stage> <run-dir> - --rehearsal --rehearsal-kind measuring --plan-file <that plan>` for `gates, train, evaluate, controls, combined, recompute, analysis, report`, one fresh process per stage and worker processes for the tasks: the same launch script, entry point (`partt_stages.execute_stage`), runner and workers as a registered run (a test asserts only the mode differs). The non-task stages run under a cap and the memory guard like the task stages.
   - **The rehearsal draw is cleaned (ruling 24):** every item of the rehearsal training draw whose normalized output equals a normalized stand-in reference is dropped, by the rule Part Q applied to evaluation references, and the number dropped per capability is recorded (`rehearsal_draw.json`, and in the rehearsal record). Gate G1 then runs unchanged and must pass; it is never weakened or made report-only.
   - It holds no evaluation item (`partt_rehearsal.rehearsal_bundle`, ruling 16: D_cal split by identity group into four disjoint parts, three standing in for E_A, E_B, E_C; the code refuses a bundle holding an E or Q_check item). Its scores, per-item records, analysis and label-worded report are written under `<run-dir>/sealed/` and are not displayed.
   - Writes `rehearsal_measuring.json`: `caps_formula = partt-whole-process-v1`, `rates_seconds_per_unit` for every kind the plan holds (GEN folded into `score:plain`, ruling 18), `overhead_seconds` per stage, `subset_units`, `subset_processes`, and per worker the process-tree and own peak RSS, MPS memory, disk written, load at start and end, with the other studies alive.
   - Pass: `status` COMPLETE and `problems` empty. **Resume:** run the same command again; complete stages are skipped and an INCOMPLETE record is kept as `rehearsal_measuring.attempt<n>.json` beside the new one.
   - Watch: the presence of a `keys` field in the real Q_check batch files (G1 reads it), worker RSS and MPS `driver_allocated`, world-build seconds, R-icl seconds per item, the size of the evaluate result files and of `item_records.json`, the G4-MPS margins.
2. **The cap for calibration.** `$Q caps-proposal --measuring-rehearsal <record> --phase calibration` prints it; `$Q caps-config --measuring-rehearsal <record> --phase calibration --apply` writes `calibration_hours` (2 x the projected calibration charge: the measured per-update rates x the 36 calibration units, plus D_cal scoring per unit at D_cal's real size, `data.d_cal_panel = 500`) into `[stage_caps]` and nothing else; commit the config. Calibration refuses while this cap is 0.
3. **Calibration** (MPS; scores D_cal only; capped; its draws may overlap the registered draws and the record STATES the overlap, ruling 2). `cd "$REPO" && $Q calibrate --part-q-dir "$PQ" --part-q-plan "$PQPLAN" --repetition 0`.
   - There is ONE calibration (ruling 21): it lives in `<main experiments directory>/P10IS2-T-calibration` (derived, no path argument), writes `calibration_0.json` once, charges `charged_ledger.json` there, and appends `start` and `end` (or `stopped`) lines to the tracked `results/p10is2-partt-calibration/CALIBRATION_LOG.jsonl` (commit it). A cap stop or a stop of any kind is logged and returns to the lead: it is not re-drawn.
   - The single repetition of section 7.1 rule 4 (only when a training or scoring file changed after the first): `--repetition 1` writes `second/calibration_1.json` and needs a COMMITTED lead record `results/p10is2-partt-calibration/REPETITION.md` with a line `reason: ...` and a line `commit: <40-hex>` naming the code change that forced it (an ancestor of HEAD); the first is kept; the plan takes the record `calibration.repetition_used` picks (the first when both match the frozen files); a code edit alone never switches the record.
   - **A stopped calibration is PAUSED and resumable (ruling 25):** a cap stop, an out-of-memory or file-system error, a power loss, a kill or a non-finite value stops the session; run THE SAME COMMAND again. A `start` without an `end` gets an appended `INTERRUPTED` line with the reason found (or UNKNOWN), the session continues from the stored per-unit state (`state/<unit>.json`: a finished unit is read back, never drawn again; a non-finite outcome is that unit's recorded outcome and is not retried) and gets what is left of the cap. The log is never edited by hand. Each session charges the ledger under its start UTC.
   - **Commit the log after each session (ruling 26).** The plan and the freeze read the calibration log from git HEAD and refuse a working file that differs from HEAD, a history that is not append-only, and a ledger whose sessions do not match the logged ones.
   - Part Q is read through the checked door built from Part Q's manifest AND its plan (`generation/result.json` is listed only in the plan's reuse list).
   - Pass: `pilot.passed` true. A stop (every rate diverged, a non-finite value, a failed pilot, the cap) returns to the lead.
4. **Candidate plan.** `cd "$REPO" && $Q candidate-plan --run-dir "$EXP/P10IS2-T-registered-<date>" --part-q-dir "$PQ" --part-q-plan "$PQPLAN" --measuring-rehearsal <rehearsal_measuring.json> --manifests <json naming part_q_acceptance and panel_ledger by path and SHA-256> [--supersede]`. No calibration path is given: the plan takes the one calibration directory's record by the rule, pinned by SHA-256, and PINS the measuring record by SHA-256.
   - Writes `studies/p10is2/freeze/partt_plan.json`: U, rates, layer and pilot from the calibration record, Part Q's run directory and manifest by hash (every Part Q file read is re-hashed through `partt_door.PartQDoor`; a difference is PAUSED — IDENTITY), the **charge before the freeze (the measuring rehearsal's and the calibration's ledgers, listed by rule)**, the unit basis, and **`counting_allowance_hours`** (ruling 20): 2 x the projected counting charge (subset units x measured rates, the training units scaled by the calibrated U over the measuring rehearsal's 200 updates (ruling 27), + processes x per-stage overhead + 2 x the training stage's overhead), fixed BEFORE the counting rehearsal runs.
5. **Registered caps by code** (they need U). `$Q caps-proposal --measuring-rehearsal <record>` prints them; `$Q caps-config --measuring-rehearsal <record> --apply` writes every other cap and `caps.provisional = false` (refused unless the calibration cap in the config is the one the record gives, and unless every cap is still 0.0: written once, by code). Total cap = plan charge + counting allowance + 2 x projected registered stages. Commit the config, run step 4 again with `--supersede`, commit the plan. Pass: `partt_caps.zero_caps` is empty.
6. **Counting rehearsal** (hours; only when the lead says so). `sh studies/p10is2/launch/partt_rehearse.sh counting "$EXP/P10IS2-T-counting-<date>" --part-q-dir "$PQ"` against the candidate plan itself, one cell of each trained type at the **calibrated full U** (ADR section 11 item 5, ruling 27: the 500-update checkpoint and stability at full U are rehearsed; the measuring rehearsal stays at 200), through `partt_registered.sh <stage> <run-dir> - --rehearsal`, with ONE forced pause (the cell `train|M1|AB|r0` stops after U/2 updates, exit 74, and the same command resumes it from its checkpoint) and ONE forced PAUSED — IDENTITY (the stage launched with a plan copy whose frozen hash is altered exits 75 and writes nothing; the real plan then runs). The forced events are recorded once in `forced_events.json`; a resumed rehearsal does not run them again and a complete stage is not started again.
   - Writes `rehearsal_counting.json` (stage statuses from the real manifests and markers, `forced`, the plan file's SHA-256, `g4_mps`, `charged_ledgers`, `charged_seconds`). Pass: COMPLETE; both `forced` flags true; `g4_mps.passed` true (gate G4 against MPS must have RUN on this machine).
7. **Freeze.** `cd "$REPO" && $Q freeze --measuring-rehearsal <record> --counting-rehearsal <record> --attest-sealed-unopened lead,implementer,auditor`; then commit. It refuses: provisional or zero caps (calibration's included); caps that differ from the rule applied to the record; an INCOMPLETE measuring record or one the plan does not pin by SHA-256; a plan that differs from a re-derivation from the current code, config, calibration record and ledgers (the differing fields are named); a calibration record that is not the one calibration directory's (by the rule), a session the log does not list, or a calibration that charged more than its cap; a charge before the freeze that is not the sum of its ledgers now, or ledgers that omit the measuring rehearsal's or the calibration's; a Part Q manifest, plan, acceptance or panel ledger that differs from its recorded hash; gate G9; a counting record that is not complete, lacks the forced events or names another plan file; and (ruling 20) a counting charge above the allowance (an engineering stop: re-plan with `--supersede`, no cap edited by hand). Writes `partt_freeze_record.json` with `pre_freeze_charge` (the registered ledger starts from plan charge + the actual counting charge).
8. **Decision 2.** `results/p10is2-partt-freeze-<date>/DECISION_2_PARTT.md` with the full freeze commit and the line `DECISION: RUN`, committed by the human lead. Without it every registered launch refuses (exit 2).
9. **Registered stages**, each `sh studies/p10is2/launch/partt_registered.sh <stage> "$EXP/P10IS2-T-registered-<date>" <full freeze commit>` in this order. Each refuses unless the tree is clean, the freeze commit is an ancestor of HEAD, the frozen files equal their content there, the plan and freeze record agree, Decision 2 is committed, and its predecessor's `stages/<stage>.complete.json` exists.

   | stage | what it does | writes | pass condition |
   |---|---|---|---|
   | `gates` | G1-G9 (G1 on the real partition, Q_check by English key only, ruling 19) | `gates.json` | status PASSED; a failed gate is ENGINEERING-FAILURE and nothing further runs but the analysis |
   | `train` | 54 cells in dependency waves, MPS, checkpoints every 500 updates | `snapshots/`, `tasks/train/*` | all 54 result files; a non-finite cell stops (never resumed) |
   | `evaluate` | per replicate and the references: every registered score on CPU, the learned routers trained and **snapshotted with hashes**, **per-item scores and greedy sequences stored**, in CONSOLIDATION-REJECTED M-ii cells the pinned M-append snapshot read in M-ii's place, marked (R13, ruling 9) | `registry.json`, `side_records.json`, `item_records.json`, `snapshots/routers/` | merged once at the end |
   | `controls` | checks that every control key the plan names is in the registry; scores nothing again (ruling 12); capped and memory-guarded | `stages/controls.*` | no missing key |
   | `combined` | C1 and C2 on the twelve arm-cells per replicate, the references, the ensemble integrity check | `combined.json`, `ensemble_check.json` | a failed ensemble check is ENGINEERING-FAILURE |
   | `recompute` | re-scores every snapshot on CPU from the snapshots and the **stored routers**, compares with the registry, the combined means and the **stored per-item records**; capped and memory-guarded (a PAUSE loses its progress: it restarts with what is left of its cap) | `recomputation/attempt_<n>.json` | `ok` true; a difference is exit 5 and nothing is labelled |
   | `analysis` | labels, tables, annotations | `analysis.json`, `report.txt` | refuses while an item error or a failed recomputation stands |
   | `report` | the report with the tables, companions, annotations and cost lines | `report.txt` | the fixed oracle-assisted line above every block |

   A stage stopped by its cap, the memory guard or an identity difference is PAUSED (exit 4 or 75; `stages/<stage>.paused.json` for the guard): run the same command again.

## Independent recomputation from what is stored

`studies/p10is2/partt_items.py` recomputes, in plain Python with no model or engine, every figure that rests on items from `item_records.json` (the mean of the stored per-item scores, the exact-match rate) and compares with `registry.json`; `gen:*` and `modification` rest on no item list and are listed apart. A test at test size reproduces every item-based registry value and one cell's labels from the stored records alone.

## Departures for the lead's ruling

### Ruling 6 (Q6): G1 and the Q_check groups

**What G1 requires, in the ADR's words (ADR-0025 section 8.2 and gate G1):** "Every score is on E_A or E_B: evaluation-side sentences, disjoint in identity groups from every training source ... Gate G1 requires that no evaluation reference equals a training output and that R-exact has zero hits." The ruling (Q6) adds: "Gate G1 takes the Q_check groups and keys from Part Q's partition records, read by SHA-256 from the Part Q run of record."

**What Part Q stored (file names and public keys only; no item content was opened by this work):** the bundle partition has the panels D_cal, D_con, E_A, E_B, E_C, E_open and Q_fit with their identity groups, but **no Q_check panel**. Q_check items exist only as Part Q's per-batch records `qcheck/teacher_*/block_*/batch_*.json`, whose public `keys` field lists the English keys. Those records carry no identity group per item. The ruling's "groups" are therefore not recoverable from Part Q's records.

**What my G1 checks:** (1) the P10-S2 partition gate on the bundle panels and streams, including identity-group disjointness for every item that has a group; (2) no normalized evaluation reference equals a training output and R-exact has zero hits; (3) vocabulary closure; (4) Q_check English keys, read through the checked door (each file re-hashed against Part Q's manifest), are tested for overlap with every training stream's English keys; any overlap fails G1 (ENGINEERING-FAILURE).

**What it cannot check:** identity groups of Q_check items (they carry -1, which P10-S2's gate skips). A Q_check sentence that is worded differently from every training sentence but shares an identity group with one is not detected by group.

**Could the missing groups hide a leak of a check item into training?** Yes, in one narrow way: a training item that is a paraphrase of a Q_check item (same identity group, different English key) would pass (4). It would not pass if the paraphrase were an exact key match. How likely this is I cannot state from the records. It is bounded by how Part Q drew the training pools relative to Q_check, which I did not examine. This is **PENDING LEAD REVIEW**: either accept the key-only test for Q_check, or have Part Q's group assignment for Q_check recomputed by its own code and stored (a Part Q addition, which I may not make). G1 was not weakened: the group test still runs wherever a group exists, and the added key test is stricter than before.

Ruling 19 (second addendum, `docs/decisions/ADR-0025-addendum-part-t-rulings-2.md`): this departure stands as a disclosed limitation, pending the auditor's reading of whether any Part T label reads Q_check; the report prints it.

### The A4 lines (ruling 23): implemented

The seen-item scores (M1 and M-append, the 300 seen items of Part Q's seed-250912 order restricted to the replicate's draw), the E_open scores (oracle route, S0 and the teacher on the same panel for reference), the edit-distance-1 flag of every E_A and E_B item against the replicate's training sources and the scores without those items are scored in the `evaluate` tasks, read through the checked door like everything else, stored in `item_records.json` and printed by the report as "A4 READING (reported, enters no label)". The labels read none of them (their registry keys are outside `partt_plan.required_keys`). Their units are counted in the caps (`data.seen_items`, `data.e_open_panel`).

### Audit N5 and N6

GEN is stored per window (the base and the arm's mean NLL at both decision positions, the router's decisions, the strata) and `partt_items` recomputes `gen:token64` and `gen:first_marker` from them; the code refuses to store them if they do not reproduce `general_quality`'s figures. Not item-based and not reproduced from the stored records: `modification` (recomputable from the snapshots with one's own code), route accuracy and false-trigger counts, R-exact hit counts, and the combined C1/C2 means (frozen code only). After a recorded gate or ensemble failure the `analysis` stage skips the `recompute` predecessor, runs without a registry and records ENGINEERING-FAILURE (never a scientific label).
